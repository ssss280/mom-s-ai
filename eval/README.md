# 联网搜索评测（eval/）

对一个**真实联网、结果随机漂移**的搜索模块做可复现评测：随机抽题 → 跑真实搜索 →
按客观判据打分 → 落盘 → 优化后再用同一批题回归。

结论与完整数据见 **[REPORT.md](REPORT.md)**。

## 文件

| 文件 | 作用 |
| --- | --- |
| `cases_bank.json` | 题库（25 题）。每题含 `expected_terms`（判据关键词分组，`|` 同义、`;` 分组）和 `expected_domains`（期望来源域名） |
| `harness.py` | 主程序：抽题 → 调 `web_search.search()` → 抓正文 → 评分 → 落盘 |
| `compare.py` | 把多次运行的指标并排对比 |
| `check_engines.py` | 搜索源健康巡检（哪个源还能用、多快、是否被安全验证拦） |
| `tuning/build_labels.py` | 采集标注数据（正/负样本） |
| `tuning/tune_scoring.py` | 对候选打分规则算 AUC / 精确率 / 召回率 / F1 |
| `tuning/labeled.json` | 标注结果（正 126 / 负 76，含 8 条对抗负样本） |
| `runs/<名字>/` | 每次运行的题目、逐题结果、链接体检、指标与总分 |

## 判据怎么算

`expected_terms` 写成 `"分组1a|分组1b;分组2"`：**分组内任一命中该分组**，
每题要求全部（或"全中率"少一组，记作"基本中"）命中，命中来源包括
**标题 + 摘要 + 抓到的正文**——也就是模型真正能看到的东西。

## 总分构成

```
命中正确性 35 + 非空率 20 + 链接有效性 15 + 正文可读 10 + 延迟 10 + 引擎均衡 10 = 100
```

## 注意（踩过的坑）

- **每道题之间不要反复 `reset_health()`**：会把引擎统计清零，看不出"哪个源还能用"。
  批次冷却本身只活在单次 `search()` 里，不会跨题污染；整轮开始前清一次即可。
- **引擎时通时不通**（尤其 DuckDuckGo）：同一配置连跑会有 3~5 分波动，
  所以结论看多次运行的均值，别只看最好的一次。
- 题库只读，测试结果写进 `runs/`，两次运行的产物互不覆盖。
