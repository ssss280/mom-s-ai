# OCR 评测（eval/ocr/）

把 `eval/`（联网搜索）那套「**改之前先量一遍基线，改完再用同一批题回归**」搬到 OCR 上。

## 为什么单独建这个

`tools/test_ocr.py` 验的是**逻辑**——base64 编码往返、未知引擎报错、缺 client 的提示、
`auto` 模式失败回退，5 项全过。但它**说明不了「识别得准不准」**：
OCR 的质量维度此前**一条客观度量都没有**。这个目录补的就是这个空缺。

## 怎么用

```powershell
py eval/ocr/harness.py                    # 只列题库 + 预计调用次数（**默认不跑**，防误花钱）
py eval/ocr/harness.py --dry-run          # 生成题图并落盘，不调任何 OCR（零成本，核对题目本身）
py eval/ocr/harness.py --limit 3          # 只跑前 3 题（控成本）
py eval/ocr/harness.py --all              # 跑全部 17 题
py eval/ocr/harness.py --engine tesseract # 指定引擎；本机没装会明确 SKIP，**不伪造结果**
py eval/ocr/harness.py --only c01-basic-cn,c15-extreme-blur
```

> **默认不实际运行**是刻意的：视觉 OCR 走的是付费 API，误触发一次就是钱。
> 要跑必须显式给 `--all` / `--limit` / `--only` / `--dry-run` 之一。

## 判据

| 指标 | 定义 | 方向 |
| --- | --- | --- |
| **CER** | 字符错误率 = 编辑距离(预测, 真值) / len(真值) | 越低越好，0 = 完全正确（主指标） |
| **行命中率** | 真值里每条消息是否被完整认出来 | 越高越好（辅助指标） |

两者都先**归一化**：去掉所有空白、把全角冒号统一成半角——发送者格式的差异不算错。

## 题库（`cases.json`）

17 题，分两类：

**内容类 10 题**：基础中文 / 中英混排 / 小字号 14px / 低对比度灰字 / 8 行长对话 /
深色背景 / 长消息换行 / 标点密集 / 数字金额时间 / 多人长名字。

**退化类 7 题**：在同样的内容上施加真实截图会遇到的退化——
轻微模糊 0.8、重度模糊 1.6、极端模糊 3.0、JPEG 35、JPEG 15、缩小 72%、缩小 50%（配数字题）。

退化是**后加的**，原因见下面的报告：加了才知道清晰的合成图根本测不出差距。

## 结果

**完整数据与结论见 [REPORT.md](REPORT.md)。** 一句话：

> 17 题**全部 CER = 0.0000**，含极端模糊、JPEG 15、缩小 50% 的数字题。
> 框架可用，但**这个度量方式对当前模型没有区分度**。

## 落盘

```
runs/<时间戳>-<引擎>/
├── cases.json     本次题库快照（题目改了也能回溯当时用的是哪版）
├── result.json    汇总指标 + 逐题明细（含真值、预测、编辑距离）
└── preview/*.png  生成的题图，用来人工核对判据是否合理
```

`runs/` 默认被 `.gitignore` 忽略（体积大、可重跑）；要留作证据的运行需显式加白名单，
与 `eval/` 下搜索评测的做法一致。
